# 串口协议总结表（新旧协议分组版）

> 说明：本表根据 `new协议-2025-V1.0.2.xls`、`protocol_new_handle.c`、`protocol_old_handle.c`、`protocol_old_extend_handle.c`、`protocol_transfer.c`、`protocol_public.h`、`protocol_share_header.h` 整理。目标是让第一次接触该协议的人也能快速知道：有哪些命令、命令怎么组帧、每个命令改了什么参数、代码对应到哪里。

---

## 0. 协议模块整体工作流

| 步骤 | 说明 | 对应代码/文件 |
|---|---|---|
| 1 | 串口/网口收到数据后，调用 `input_data()` 导入协议模块缓存 | `protocol_public.c` |
| 2 | 调用 `analysis_command()` 扫描缓存，逐字节尝试解析命令 | `protocol_public.c` |
| 3 | `Transfer_cmd_handle_func()` 先尝试旧协议，再尝试 BootLoader 协议，最后尝试新协议 | `protocol_transfer.c` |
| 4 | 命令解析成功后，调用 `Set_Controller_Data()` / `Get_Controller_Data()` 修改或读取全局参数 | `protocol_transfer.c` |
| 5 | 修改普通参数后进入 `Set_Controller_Data_Callback()`；修改可编程参数后进入 `Set_Controller_ProgData_Callback()` | `protocol_public.c` |
| 6 | 调用 `get_prepare_tx_buffer()` 取出回复数据，再由串口/网口发送 | `protocol_public.c` |

# 2. 新协议

新协议是二进制十六进制协议，不是 ASCII 字符串协议。它有 3 种功能头：

| 功能头 | 名称 | 用途 |
|---|---|---|
| `0xCA` | 单通道协议 | 一次设置或读取一个参数 |
| `0xCB` | 多通道协议 | 一次设置多个通道的同一类参数 |
| `0xCC` | 可编程协议 | 设置可编程表格、步数、触发模式等 |

校验字使用 BCC 异或校验：从功能头开始，把前面所有字节逐个异或得到 1 字节校验值。

注意：代码中 `CRC_ENABLE = 0`，也就是当前即使 BCC 不匹配，默认仍会继续解析；如果希望严格校验，需要把它改为 1。

---

## 2.1 新协议：单通道帧 `0xCA`

### 2.1.1 单通道设置帧

| 字节序号 | 字段 | 长度 | 示例 | 说明 |
|---:|---|---:|---|---|
| 0 | 功能头 | 1 | `CA` | 单通道 |
| 1 | 命令字 | 1 | `01` | 例如设置亮度 |
| 2 | 通道号 | 1 | `01` | 通道 1 |
| 3~4 | 数据字 | 2 | `00 FF` | 大端，高字节在前，表示 255 |
| 5 | BCC | 1 | `XX` | 前 5 个字节异或和 |

例子：设置 1 通道亮度为 255：

```text
CA 01 01 00 FF XX
```

### 2.1.2 单通道读取帧

读取帧格式与设置帧相同，只是命令字换成读取命令，数据字可填 0。

例子：读取 1 通道亮度：

```text
CA 61 01 00 00 XX
```

### 2.1.3 单通道回复

| 场景 | 回复格式 | 说明 |
|---|---|---|
| 设置成功 | `功能头 命令字 通道号 00` | `00` 表示成功 |
| 设置失败 | `功能头 命令字 通道号 错误码` | `01` 不支持，`02` 通道溢出，`03` 数据溢出 |
| 读取成功 | `功能头 命令字 通道号 数据高 数据低 BCC` | 返回 2 字节数据 |

---

## 2.2 新协议：多通道帧 `0xCB`

多通道协议用于一次设置多个通道的同一个命令。代码中多通道只支持“写指令”，不支持多通道读取。

| 字节序号 | 字段 | 长度 | 示例 | 说明 |
|---:|---|---:|---|---|
| 0 | 功能头 | 1 | `CB` | 多通道 |
| 1 | 命令字 | 1 | `01` | 例如设置亮度 |
| 2 | 通道数 | 1 | `02` | 后面有 2 组通道数据 |
| 3 | 通道号1 | 1 | `01` | 通道 1 |
| 4~5 | 数据字1 | 2 | `00 FF` | 通道 1 的值 255 |
| 6 | 通道号2 | 1 | `03` | 通道 3 |
| 7~8 | 数据字2 | 2 | `00 0A` | 通道 3 的值 10 |
| 9 | BCC | 1 | `XX` | 前面所有字节异或和 |

例子：设置通道 1 亮度 255，通道 3 亮度 10：

```text
CB 01 02 01 00 FF 03 00 0A XX
```

# 3. 旧协议

旧协议主要是 ASCII 字符串协议，以 `#` 作为结束符。通道使用 `A~H`，其中 `A` 对应新协议通道 1，`B` 对应通道 2，以此类推。

---

| 旧协议 | 频闪 | `CT0#`/`CT1#` | 写 | 设置相机触发边沿 | 回复 `ct` | 0 上升沿，1 下降沿 |
| 旧协议 | 频闪 | `CT#` | 读 | 读取相机触发边沿 | 回复 `ctX` | X 为 0/1 |
| 旧协议 | 公共 | `SWTRIG#` | 写 | 软件触发 | 回复 `#` | 代码只回复，没有调用新协议的 `Set_softwareTrig` |
| 旧协议 | 公共 | `SAVE#` | 写 | 保存参数 | 回复 `#` | 是否真正写 Flash 需要外部回调实现 |
| 旧协议 | 公共 | `CST` | 读/心跳 | 心跳测试 | 回复 `CST` | 代码未要求 `#` 结束 |
| 旧协议 | 可编程 | `PRCL#`、`PRWA#`、`PRNA...#`、`PRENCLRA#` | 占位 | 可编程相关旧命令 | 当前都转到 `TPX_CMD` | 实际不可按名称理解，代码像占位/未完成 |

## 3.2 旧协议：扩展 ASCII 命令 `$` / `@`

扩展旧协议比普通旧协议更规整：`$` 表示写，`@` 表示读，后面跟 2 位功能号。

### 3.2.1 扩展写命令格式

```text
$ + 功能号2位 + 通道块1 + 通道块2 + ... + #
```

通道块格式：

```text
通道字母 + 0 + 3位数据
```

例子：设置 A 通道亮度为 123：

```text
$01A0123#
```

例子：一次设置 A 通道 123、B 通道 456：

```text
$01A0123B0456#
```

写成功统一回复：

```text
$
```

### 3.2.2 扩展读命令格式

```text
@ + 功能号2位 + 通道字母1 + 通道字母2 + ... + #
```

例子：读取 A、B 通道亮度：

```text
@01AB#
```

回复格式：

```text
@ + 功能号2位 + A + 4位数据 + B + 4位数据 + #
```

例如：

```text
@01A0123B0456#
```

### 3.2.3 扩展功能号表

| 功能号 | 小类 | 功能 | 对应新命令 | 代码状态 |
|---:|---|---|---|---|
| `00` | 公共 | 软件版本 | - | 枚举有定义，但解析范围从 01 开始，实际不可用 |
| `01` | 数字 | 亮度 | `Set/Read_Brightness` | 可用 |
| `02` | 频闪 | 脉宽 | `Set/Read_Pulse_width` | 可用 |
| `03` | 频闪 | 脉宽单位 | `Set/Read_Pulse_width_unit` | 可用 |
| `04` | 公共/频闪 | 工作模式 | 实际映射到 `Set_trigger_mode` | 可用但有特殊转换：0001→0，0004→1，0006→2 |
| `05` | 数字 | 通道开关 | `Set/Read_Channel_Switch` | 可用 |
| `06` | 频闪 | 光源延时 | `Set/Read_Light_delay` | 可用 |
| `07` | 频闪 | 相机延时 | `Set/Read_Camera_delay` | 可用 |
| `08` | 数字 | 数字常亮/常灭 | `Set/Read_Digital_trigger_mode` | 可用 |
| `09` | 频闪 | 内触发周期 | `Set/Read_Trigger_cycle` | 可用 |

# 4. 代码实现重点和注意事项

| 问题点 | 说明 | 建议 |
|---|---|---|
| 新旧协议共存 | `Transfer_cmd_handle_func()` 先解析旧协议，再 BootLoader，再新协议 | 如果新协议某字节刚好像旧协议开头，理论上旧协议优先 |
| BCC 默认不强制 | 新协议计算 BCC，但 `CRC_ENABLE=0` 时校验不通过也继续执行 | 正式产品建议打开或增加错误回复 |
| Excel 与代码不完全一致 | Excel 写配方/触发源 1~8，但代码当前是 1；Excel 表格帧相机输出像 2 字节，代码实际 1 字节+1 字节保留 | 应以代码为准，或同步修改 Excel/代码 |
| 通道 0 风险 | 文档部分命令说通道 0 表示全部，但 `Set_Controller_Data()` 对亮度/色温/脉宽/延时类直接禁止通道 0；通道开关也没有遍历全部通道 | 若需要“全部通道”，建议在代码中明确循环 1~8 |
| 新协议读取通道 0 风险 | `Read_Data_NEWcmd()` 只判断 `channel > CHANNEL_NUM`，没有禁止 `channel==0`，某些读取会访问 `channel-1` | 对通道型读取应增加 `channel == 0` 判断 |
| 旧协议部分命令未真正实现 | 例如 `SWXXXX#`、`DC0XXX#`、`PR...` 等存在回复，但没有完整修改全局参数 | 对外文档中应标注“占位/不建议使用” |
| 旧协议 `SPUXX#` 疑点 | 设置脉宽单位时传入 ASCII `'0'/'1'`，不是数值 0/1 | 建议改成 `uart_buf[i+4]-'0'` |
| 模块化型号初始化 | `controller_model={ModulStrobe, CHANNEL_NUM}`，但初始化监控只判断 `Digital` 和 `Strobe` | 如果模块化也要初始化数字/频闪默认值，需要补分支 |

# 5. 小白速记版

| 你想做什么 | 用哪个协议最合适 | 命令怎么理解 |
|---|---|---|
| 设置某一路亮度 | 新协议单通道 `CA 01` | CA=单通道，01=亮度，通道号=哪一路，数据=亮度值 |
| 一次设置多路亮度 | 新协议多通道 `CB 01` | CB=多通道，01=亮度，后面跟多组“通道+值” |
| 设置频闪脉宽 | 新协议 `CA 21` 或 `CB 21` | 21=脉宽，决定灯亮多久 |
| 设置光源延时 | 新协议 `CA 22` 或 `CB 22` | 22=光源延时，决定触发后延迟多久点亮 |
| 设置相机延时 | 新协议 `CA 23` 或 `CB 23` | 23=相机延时，决定相机信号什么时候输出 |
| 设置工作模式 | 新协议 `CA 41` | 41=模式切换 |
| 做多步骤亮度/脉宽表 | 新协议 `CC 01` | CC=可编程，01=写表格，每一行是一组动作 |
| 兼容旧上位机 | 旧协议 `SA0255#` 等 | ASCII 命令，以 # 结束，A~H 代表 1~8 通道 |
