# Command Atlas 美术定稿 V2

> 决策日期：2026-09-28。用户授权依据两款设计选择或融合；本文件确定最终风格。V1 与两款候选保留作参考，存在冲突时以本文件为准。
> 适用工程：`01_Software/command_atlas/`。设计预览：`design/approved.html`。这是样式与布局定稿，Qt 应用接入仍按分阶段计划实施。

## 1. 最终选择与依据

风格名称：**工程图集 · 字段解剖**。采用 `design/index.html` 的双栏查询布局、分组字节图与操作区，融合 `design/mockup.html` 的浅色纸面、Atlas 蓝配色和一致的控件规范。

| 比较项 | 定稿 | 原因 |
|---|---|---|
| 查询布局 | 左侧结果，右侧详情/参数/帧/操作 | S1 已验证这一结构，售后操作路径集中，1180px 窗口仍有足够组帧空间。 |
| 最近/收藏/版本信息 | 收藏和最近在 S4 加入左侧次要入口；详细数据放同步页 | 不占据常驻第三栏。查询页只保留简短数据状态。 |
| 配色 | 沿用 V1 的 Atlas 蓝 `#2456E6` 和浅灰/白底 | 两个稿与当前 QSS 使用的蓝色不同，最终统一为同一套 Token。 |
| 帧预览 | 沿用重设计稿的字段分组、括号与字节坐标 | 一组明确表示一个字段，尤其是亮度的两个字节或旧协议的多个 ASCII 数字。 |
| 主操作 | 按模板 `frame_format` 决定优先复制 HEX 或 ASCII | 新协议与旧协议的常用文本不同；导出是次操作。 |
| 研发录入 | 左草稿列表、中编辑、右预览；窄窗口预览可收起 | 研发需要同时核对参数与帧，三栏用于编辑页，不用于售后查询页。 |
| 同步页 | 状态、配置和数据版本分组展示，日志折叠 | 售后默认只需知道本地数据可用和同步结果。 |

仅一个浅色主题，帧区域使用深色。参数表单、滚动区域 viewport、菜单、弹出列表和状态栏都要显式设置背景与文字；统一 QPalette/QSS，避免 Windows 深色模式透出黑底。用户 S1 截图中的参数区黑底、深色标签，以及底部状态文字对比不足，列为样式接入时必须修正的项目。

字体使用 Windows 自带的 Microsoft YaHei UI 与 Consolas。2026-09-28 用户要求整体更小、更紧凑：Qt 正文、控件、辅助说明和原始帧文本统一 9pt，区块标题 10pt，指令/编辑器标题 15pt，品牌 16pt。HTML 预览保留先前布局示意，最终尺寸以本次紧凑规范与 Qt 实现为准，不将 CSS px 直接当 Qt pt。

采用紧凑间距：控件间距 6~8px、区块间距 8~10px、页面边距 12~16px。面板圆角 6~7px、输入框/按钮 5px、字节块 4px。按钮总高度约28px、输入框约30px（Qt逻辑尺寸）；保留清晰的边框、焦点与禁用状态。

## 3. 查询与组帧页

1. 顶部紧凑品牌栏：应用名、中文说明、一个本地数据状态。保留 Windows 原生标题栏。
2. 搜索/筛选栏：产品、协议、宽搜索框。参数数值由表单填写；占位文字只描述当前实际支持的名称、用途、别名、关键词搜索。
3. 左结果栏通常宽 280~300px，选中条目用浅蓝底、蓝色细标识与明确文字。条目显示名称、协议和类别。
4. 右详情依次为：指令名称与适用范围 → 简短说明/示例提示 → 参数 → 分组帧预览 → 原始 HEX/ASCII → 操作区。
5. 参数标签位于输入框上方或同一行左侧。通道和值可并排；每项旁边显示范围和编码，错误文案紧邻输入框。仅保留足够实际参数使用的高度。
6. 复制操作位于详情下方，独立于可滚动内容；主复制按钮为蓝色实心，另一格式复制为描边，导出文本为次级按钮。复制成功短暂显示“已复制”。

紧凑版查询窗口默认1040×680、最小900×580；研发窗口默认1120×700、最小980×600。查询列表双行条目高度44px，编辑表格默认行高26px；研发帧段新增与编辑动作分两行，减少最小宽度限制。高 DPI 继续使用 Qt 逻辑尺寸与布局，沿用系统缩放。

## 4. 字段图的通用规则

帧段、参数、校验都来自模板，图形不硬编码具体控制器语义：

- 按有序帧段分组。固定段显示“固定段”，参数段显示其中文标签和当前值，计算段显示算法名称。当前样例的 `CA 01` 是一个固定段，不能为美观擅自将其解释成两个模板字段。
- 同一字段的多个字节/字符放在一个括号下。新协议亮度 `00 FF` 是一个两字节字段；旧协议亮度 `255` 是一个三字符字段。
- 坐标注明“字节偏移，从 0 开始”，完整字节范围由组帧结果累计得到。通道 A~H 和数字补零按编码实际显示。
- 新协议以 HEX 显示字节；ASCII 协议优先显示可读字符，并同时提供完整 HEX 与 ASCII 原始文本。
- 编辑某参数时，对应组描边高亮，不改变值或触发设备操作。长帧在预览区横向滚动，原始文本始终可选中和复制。
- 模板使用 XOR BCC 才显示 BCC 组与结果，旧 ASCII 模板不制造不存在的校验字段。

## 5. 研发与同步页沿用的规范

S2 编辑页采用左草稿列表、中表单/帧段表、右实时预览。身份信息、检索字段、适用产品、参数定义、固定/参数/计算段按已批准字段组织。显示新建、未保存、已保存与导出结果；正式库与草稿来源清楚。窄窗口可收起预览或上下排列。

S3 数据页顶部显示本地可用/更新中/同步完成/同步失败四类状态及短句。版本与同步时间作普通信息，仓库/项目ID作配置项，提交与技术日志放展开详情。失败时说明仍使用哪份本地数据，不能显示未实现校验的“全部通过”。

S4 收藏与最近使用在查询左栏增加分组入口。图标统一 16/20px 线性 SVG；应用图标后续采用“图集页 + 字段分组/定位”方向，产出正式 SVG/ICO 后再接入，候选里的字母 A 或定位符不视为已完成应用图标。

## 6. 设计稿内容与产品范围

两款候选中的型号/固件选择、自然语言自动提参、匹配原因评分、风险 L0~L3、黄金向量编辑、回复定义、导出到串口工具和手动快照回退，并非由美术稿自动获得功能授权。本次定稿不增加这些需求；后续需要时按产品决策登记。

定稿预览采用已验收 S1 的真实样例形式：通道 1~8，亮度 0~999，新协议 `CA 01 01 00 FF 35`、旧协议 `SA0255#`、旧扩展 `$01A0123#`。设计稿仅是展示与参数联动示意，正式模板及 FrameBuilder 才是软件字节来源。
