面向只学过 C、做过单片机、对 C++/Qt 了解不多的工程师。目标：让你快速看懂这个工程每一块代码在做什么，同时用这个真实项目当“课本”，有针对性地把 C++/Qt 最该先掌握的知识补上。

0 · 这份指南怎么用

你已经有 C 的底子（变量、函数、指针、结构体、数组、while(1) 主循环、中断），这是巨大的优势——C++ 是 C 的超集，你写的 C 代码在 C++ 里几乎都成立。难点只在三件事：

  1. 面向对象：把“数据 + 操作数据的函数”打包成类（class）。
  2. Qt 的信号槽：对象之间用“发信号/收信号”通信，本质就是你熟悉的回调函数，只是更安全更自动。
  3. 事件循环：桌面程序没有 while(1)，靠一个隐藏的“事件循环”驱动，跟单片机的中断 + 主循环思路一致。

建议阅读顺序：先看 第 1 节 和 第 2、3 节建立概念 → 再看 第 4 节整体结构 → 然后挑 PacketBuilder（最像 C）和 AutoSendEngine（核心）精读 → 最后照 第 8 节路线补课、做 第 9 节练习。

📌 约定
本文出现 基础 的概念是你现在就要懂的；进阶 的可以先跳过，等读到对应模块再回来。

1 · 30 秒看懂这软件是什么

它是一个 Windows 上的串口调试 + 自动测试工具，比普通串口助手多了四样定制功能：

功能通俗说
串口收发开关串口、手动发 HEX/ASCII、带时间戳显示、可选 BCC 校验
协议指令库把设备的 132 条协议命令存成一个库，可分组查看/增删改/搜索
自动发送选一条命令，每隔 N 毫秒发一次，发 M 次
检测统计自动比对“发出去的”和“收回来的”，算出丢包率 / 回复正确率 / 总成功率，并写日志

界面是 5 个标签页（Tab）：串口收发 / 指令库 / 自动发送 / 结果与日志 / 设置。

2 · 从 C 到 C++/Qt：先建立这 8 个新概念

下面每个概念都对照 C 来讲，并指出在本工程哪里能看到。

基础 ① 类 class = 升级版 struct

C 里你会这样把数据和函数分开：

// C 风格
struct Serial { int fd; };
int serial_open(struct Serial* s, const char* port);  // 函数和数据分离

C++ 把“数据 + 操作它的函数”装进同一个 class，函数叫成员函数，通过 对象.函数() 调用：

// 本工程 core/SerialTransport.h（简化）
class SerialTransport {
public:
    bool open(const QString& portName, qint32 baud, ...);  // 成员函数
    bool send(const QByteArray& data, ...);
private:
    QSerialPort m_serial;   // 成员变量（数据），m_ 前缀是本工程约定
};

用法：m_transport.open("COM3", 115200, ...)。

对照记忆：public: 外面能用，private: 只有自己能用（C 没有，靠自觉）。成员变量加 m_ 前缀是为了一眼区分“这是对象自己的数据”。

基础 ② 头文件 .h / 源文件 .cpp / #pragma once

和 C 完全一样：.h 放声明（有哪些类、函数长什么样），.cpp 放定义（函数体）。#pragma once 等价于你写过的 #ifndef XXX_H / #define / #endif 防重复包含，只是一行搞定。

基础 ③ 引用 &：比指针更安全的“别名”

C（指针）C++（引用）
void f(int* p){ *p = 5; }
f(&x);		void f(int& r){ r = 5; }
f(x);

引用就是变量的“别名”，不能为空、不用解引用。本工程里大量出现 const QString&——意思是“传进来一个字符串，我只读不改，而且不拷贝（高效）”。

bool send(const QByteArray& data);   // const 引用：高效传参 + 承诺不修改

基础 ④ Qt 的“C 库替代品”：字符串和容器

单片机里你用 char buf[64] 和手写数组。Qt 给了更好用、自动管内存的工具，用法直觉化、不用自己 malloc/free：

你在 C 里用本工程用的 Qt 类干啥
char[] + strcpyQString文本字符串（界面文字、命令名）
uint8_t[]QByteArray原始字节（串口收发的数据）
手写动态数组QList<T>列表（132 条指令存在 QList<CommandItem> 里）
查表QHash<K,V>键值映射（日志里“路径→文件句柄”）
🔑 关键差异：这些类自己管理内存——出了作用域自动释放，不会内存泄漏。这是 C++ 的 RAII 思想（见概念⑥），是它比 C 省心的最大原因之一。

基础 ⑤ 命名空间 namespace

就是给一组函数/常量加个“姓”，避免重名。本工程 PacketBuilder 就是一个命名空间，调用时写 PacketBuilder::fromHexText(...)，:: 读作“的”。

进阶 ⑥ 构造/析构 与 RAII（对象的“出生”和“死亡”）

C++ 的对象有两个特殊函数：构造函数（创建时自动调用，相当于初始化）和析构函数（销毁时自动调用，相当于清理）。这套机制叫 RAII：资源（内存、文件、串口）在对象出生时获取、死亡时自动归还。

LogManager::~LogManager() {   // ~ 开头 = 析构函数，对象销毁时自动跑
    if (m_sessionActive) endSession(...);  // 程序关掉前补写日志，不丢数据
    m_thread.quit(); m_thread.wait();   // 关掉后台线程
}
对照单片机：你以前要手动 close(fd)、手动 free()，忘了就泄漏。C++ 把“清理”绑定到析构函数，对象一销毁就自动执行，少一大类 bug。

进阶 ⑦ 指针 * 与 new：界面控件都是 new 出来的

Qt 的界面控件（按钮、输入框）必须用 new 在堆上创建，并指定一个父对象（parent）。关键点：父对象销毁时会自动 delete 所有子对象，所以你几乎从不手动 delete 控件。

auto* btn = new QPushButton("发送", this);  // this = 父对象；窗口关了，按钮自动释放

auto 是“让编译器自动推断类型”，省得写一长串类型名。

进阶 ⑧ 事件循环：桌面程序的“主循环”

// main.cpp —— 整个程序的入口
int main(int argc, char* argv[]) {
    QApplication a(argc, argv);
    MainWindow w;
    w.show();
    return a.exec();   // ← 这一行就是 while(1)！事件循环：等事件→分发→处理
}
🔑 思维迁移：单片机是 while(1){ 处理(); } + 中断打断。桌面是 a.exec() 这个事件循环在转，鼠标点击、串口来数据、定时器到点……都变成“事件”被分发到对应的处理函数。你不写循环，你只写“当 X 发生时该怎么办”。这正好引出下一节的信号槽。

3 · 信号槽 = 软件版的“中断回调”（最重要！）

这是 Qt 的灵魂，也是 C 工程师最需要转过弯的点。先用你熟的东西类比：

单片机Qt 信号槽
串口收到字节 → 触发中断 → 跳到中断服务函数串口收到字节 → 发出信号 bytesReceived → 调用连接的槽函数
你在初始化时注册中断向量你在初始化时用 connect() 把信号接到槽

信号（signal）＝“某件事发生了”的通知；槽（slot）＝收到通知后要执行的普通函数；connect＝把两者连起来（注册回调）。看本工程真实例子：

// 串口对象“收到数据”这件事，交给基础页的 onBytesReceived 处理
connect(m_transport, &SerialTransport::bytesReceived,
        this,        &BasicSerialPage::onBytesReceived);
//        ↑发信号的对象   ↑哪个信号                ↑收的对象  ↑用哪个槽函数

之后 SerialTransport 内部只要 emit bytesReceived(data);（发射信号），onBytesReceived(data) 就会被自动调用——发信号的人完全不需要知道谁在听，这就是解耦。

为什么比 C 的函数指针回调好？
① 一个信号能接多个槽（本工程串口数据同时给“显示”和“引擎统计”）；② 对象销毁时连接自动断开，不会像 C 那样回调到已释放的对象上导致崩溃；③ 还能跨线程安全传递（日志线程就靠它）。

5 · 模块逐个讲

📦 PacketBuilder —— 最像 C，建议从这里读起

职责：纯粹的数据转换工具，没有界面、没有状态、没有对象——就是一组函数，和你写单片机里的 hex2bin() 一模一样。它放在 namespace PacketBuilder 里。

// 把 "CA 01 0A" 这样的文本，转成真正的字节 {0xCA,0x01,0x0A}
QByteArray fromHexText(const QString& text, bool* ok);
// 逐字节异或，算出 1 字节 BCC 校验
quint8 bccXor(const QByteArray& data);

BCC 计算和你在单片机里写的完全一样：

quint8 bccXor(const QByteArray& data){
    quint8 bcc = 0;
    for (const char b : data) bcc ^= (quint8)b;  // 范围 for：遍历每个字节
    return bcc;
}
新语法点：for (const char b : data) 叫范围 for，等于“对 data 里的每个字节 b”，比 C 的 for(i=0;i<n;i++) 简洁。quint8 就是 Qt 给 uint8_t 起的名字。
这里曾有个真 bug（已修）：判断字符是否是十六进制，原来用 C 的 isxdigit()，但传入非 ASCII 字符（如中文/重音字母）时是未定义行为，可能崩溃。改成手写范围判断 (u>='0'&&u<='9')||... 才安全。教训：C 标准库的 isxxx() 函数对“负的 char”有坑。

🔌 SerialTransport —— 把 Qt 的串口包一层

职责：封装 Qt 自带的 QSerialPort，对外只暴露 open/close/send 和几个信号。它不懂任何协议，只负责“原始字节进出”。

signals:                                    // 这个对象会发出的“通知”
    void bytesReceived(const QByteArray& data); // 收到字节了
    void offline(const QString& reason);       // 串口被拔了
    void portStateChanged(bool open);          // 开/关状态变了

内部把 QSerialPort 的“有数据可读”信号接到自己的处理函数，再转发成自己的 bytesReceived 信号：

void SerialTransport::onReadyRead(){
    QByteArray data = m_serial.readAll();
    if (!data.isEmpty()) emit bytesReceived(data);  // 转发出去
}
为什么要“包一层”而不直接用 QSerialPort？这叫封装：把第三方库藏在自己的简单接口后面。好处是上层代码只认 bytesReceived，将来哪怕换成 TCP，只要发同样的信号，上层一行都不用改。

🗂️ CommandItem + CommandLibrary —— 数据结构 + 存盘

CommandItem 是一条指令的数据结构（就是个升级 struct），字段如发送内容、正确回复、是否加 BCC 等。CommandLibrary 管理一整个 QList<CommandItem>，并负责存成 JSON 文件（重启后还在）。

// 内存里就是一个列表；增删改查都在这个列表上操作
QList<CommandItem> m_items;
// 存盘：把列表转成 JSON 文本写文件（QJsonDocument/QJsonArray 是 Qt 自带）
JSON 是什么？一种人类可读的文本数据格式，像“带括号的配置文件”。Qt 自带读写工具，不用自己解析。打开 resources/default_commands.json 看一眼就懂了。
修过的坑：首次运行要把内置 132 条写到用户目录，原来没检查“写失败”就当成功了——如果目录只读，用户改的指令会悄悄丢。现在写失败会弹提示。教训：凡是 I/O（文件/串口）都要检查返回值，这点和单片机一样。

⚙️ AutoSendEngine —— 核心，一个“状态机”

职责：自动发送的大脑。它不是 while 死循环（那样会卡死界面！），而是一个事件驱动的状态机，靠定时器和信号一步步推进。这正好对应你单片机里用定时器中断 + 状态变量跑流程的写法。

两种模式

  • 开检测（ping-pong）：发一条 → 等回复或超时 → 间隔后发下一条。请求和回复严格一对一，统计才准。
  • 关检测（固定节拍）：只管按间隔发，不等回复，只数发了多少次。

一轮的生命周期（ping-pong）

void AutoSendEngine::beginRound(){
    m_rxBuffer.clear();             // 清空本轮接收缓冲
    m_roundTimer.restart();          // 开始计时（为了算响应时间）
    if (!m_transport->send(m_payload, &err)){ ... return; } // 发！
    m_stats.recordSend();           // 发成功才计数（修过的坑#6）
    m_inRound = true;
    m_timeoutTimer->start(m_timeoutMs); // 启动本轮超时定时器
}

接下来有两种结局，都由“事件”触发：

// 结局A：串口来数据了（信号触发）
void onBytesReceived(const QByteArray& d){
    m_rxBuffer.append(d);                      // 累加
    if (m_rxBuffer.contains(m_expected))      // 收到的包含正确回复？
        resolveRound(true,true, 用时);          // → 匹配成功
}
// 结局B：超时定时器到点了（信号触发）
void onTimeout(){
    bool got = !m_rxBuffer.isEmpty();
    resolveRound(got, false, -1);  // 收到过字节=回复错误；啥都没收=丢包
}
🔑 这就是“事件驱动”的精髓：函数发完就立刻返回，把界面让出去；真正的“等回复/等超时”是靠信号在未来某刻把你叫回来。所以发 1 万次也不会卡界面。对比单片机：你绝不会在主循环里 delay(100) 傻等，而是开定时器中断——一个道理。

📊 TestStatistics —— 计数与算率

纯数据类，几个 64 位计数器 + 算各种率的函数。为什么用 64 位（quint64）？因为最大发 1000 万次，虽然没超 32 位，但留余量、避免溢出，是好习惯。

double lossRate() const {            // 丢包率 = 超时数 / 发送数
    if (m_send == 0) return 0.0;     // 防止除以 0！
    return (double)m_timeout / m_send;
}
函数后面的 const 表示“这个函数只读、不修改对象”，是 C++ 给读者和编译器的承诺。看到它就知道“调它很安全，不会改数据”。

🧵 LogManager —— 唯一的后台线程（进阶）

职责：把日志写到 CSV 文件。难点：写文件慢，如果在主线程写，发 1000 万次时界面会卡。解决办法是开一个后台线程专门写文件，主线程只把“要写的行”丢给它。

m_writer = new LogWriter;
m_writer->moveToThread(&m_thread);          // 把写文件的对象搬到后台线程
connect(this, &LogManager::writeLinesRequested,
        m_writer, &LogWriter::writeLines);     // 跨线程信号：自动排队，安全
🔑 跨线程为什么安全？主线程 emit writeLinesRequested(...)，Qt 会把这次调用排队到后台线程去执行，不会两个线程同时碰同一块数据。这是信号槽除解耦外的第二大杀器。多线程是本工程最难的部分，初学可先理解“为什么要它”，实现细节后面再啃。
修过的坑：①程序中途关闭时漏写汇总行——析构里补写；②文件句柄一直不关——改成每次测试结束就关。多线程 + 文件，是最容易出资源泄漏和时序 bug 的地方，所以这块我们专门做了 code review。

🖼️ UI 页面 与 MainWindow —— 界面怎么搭

每个标签页是一个继承自 QWidget 的类。界面用代码搭（不用拖拽设计器）：new 出控件 → 放进布局（layout） → connect 信号槽。

auto* root = new QVBoxLayout(this);   // 垂直布局：控件从上往下排
m_sendButton = new QPushButton("发送", this);
root->addWidget(m_sendButton);
connect(m_sendButton, &QPushButton::clicked,   // 按钮“被点击”信号
        this, &BasicSerialPage::sendManual);    // → 接到“执行发送”槽
布局（Layout）是 Qt 自动排版器：你说“竖着排/横着排/表格排”，窗口缩放时控件自动跟着调整，不用你算坐标。对比：单片机 OLED 上你得自己算每个字的像素位置——Qt 帮你算。

MainWindow 则把 5 个页面塞进 QTabWidget（标签容器），并把核心对象的地址分发给各页。它还负责“测试运行时锁住其它标签页”这类全局协调。

6 · 一条数据的完整旅程（把所有模块串起来）

以“点开始测试 → 看到统计更新”为例，跟着信号走一遍：

  1. AutoSendPage：你点“开始测试” → 槽函数 startTest() 收集间隔/次数/指令，调 m_engine.start(cfg)。
  2. AutoSendEngine：beginRound() → 调 m_transport.send(字节) 发出去，启动超时定时器。↓
  3. SerialTransport：串口真正把字节写出去；设备回了数据 → QSerialPort 触发 → emit bytesReceived(data)。↓
  4. AutoSendEngine（接了该信号）：onBytesReceived 比对 → 匹配成功 → m_stats.recordMatch() 更新计数 → emit roundResolved() 和（失败时）roundFailed(...)。↓
  5. ResultPage（接了 roundFailed）：往异常明细表加一行。MainWindow（接了 roundCompleted）：转给 LogManager 写日志。
  6. AutoSendPage / ResultPage：各自有个 200~300ms 的刷新定时器，定时去 m_engine.statistics() 读最新数字刷到界面——不是每条都刷，否则高速时界面会卡。
🔑 看懂这张图，你就看懂了整个工程：没有谁直接调用谁的界面，全靠“发信号—接信号”。数据在 core/ 里流动和计算，ui/ 只在定时器到点时“拍个快照”显示。

7 · C 工程师最容易踩的 6 个坑

坑说明 & 怎么避
① 对象被悄悄拷贝C++ 里 QByteArray a = b; 是拷贝一份。传参想避免拷贝就用 const&。本工程大量用 const QByteArray& 正是为此。
② 悬空指针/引用页面拿的是核心对象的指针。只要核心对象比页面活得久（MainWindow 持有它们）就安全。别保存一个临时对象的地址。
③ 在槽函数里干重活槽函数运行在主线程，里面 delay 或大循环会卡死界面。耗时的事交给定时器分步做或丢给后台线程（见 LogManager）。
④ 成员初始化顺序类成员按声明顺序构造，不是按你写初始化的顺序。本工程 m_engine{&m_transport} 必须声明在 m_transport 之后，否则用到还没造好的串口。
⑤ 整数除法 & 除零和 C 一样：1/2==0。算率前先转 double，且先判分母是否为 0（见 TestStatistics）。
⑥ char 的符号char 可能是有符号的，(int)某字节 可能变负数。处理字节统一用 quint8/unsigned char（PacketBuilder 的 isxdigit 坑就是这个）。
