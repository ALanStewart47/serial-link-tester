## 基础报文

电脑 UDP 接收端口60000，设备配置端口50000；从选定网卡广播。报文固定285字节，不追加BCC。

| 报文偏移 | 长度 | 内容 |
|---|---:|---|
| 0 | 16 | `43 48 39 31 32 31 5F 43 46 47 5F 46 4C 41 47 00`，即 `CH9121_CFG_FLAG` 加零 |
| 16 | 1 | 命令 |
| 17 | 6 | 设备MAC；搜索时全零 |
| 23 | 6 | 本机所选网卡MAC |
| 29 | 1 | 有效数据长度 |
| 30 | 255 | 数据区，保留完整长度 |

| 操作 | 请求/应答 | 长度字段 |
|---|---|---|
| 搜索 | `04 / 84` | 请求00；应答长度为IP四字节加设备名（含末尾零），版本字节紧随其后，不计入长度 |
| 读取 | `02 / 82` | 请求00；应答CC（204） |
| 写入 | `01 / 81` | 请求CC；应答允许00，不能套用GET应答检查 |
| 否定应答 | `C0 / C1 / C2` | 分别为搜索、写入、读取否定应答，不作为成功 |

GET请求为上述头部、目标MAC、本机MAC、长度00及255个零。SET为相同头部、命令01、长度CC及修改后的完整255字节数据。SET_ACK只表示设备应答，必须重新读取核对才能显示“已验证”。协议没有事务序号，同MAC同命令的迟到包无法完全区分；单事务、阶段过滤和写后读回降低其影响。

## 配置布局

数据区前204字节为 `HWCfg[74] + PortCfg[0][65] + PortCfg[1][65]`。端口2在74，端口1在139。下表偏移均相对于数据区，报文绝对偏移需加30。

| 字段 | 偏移/长度 | 编码 |
|---|---|---|
| 类型/子类型/序号/硬件版本/软件版本 | 0/5 | 只读，原样保留 |
| 设备名 | 5/21 | 新名称1～20个可打印ASCII字符，零结尾；未编辑的非ASCII名称原字节保留 |
| MAC | 26/6 | 只读，应与报文目标MAC一致 |
| IP | 32/4 | 四段IPv4顺序 |
| 网关 | 36/4 | 四段IPv4顺序 |
| 掩码 | 40/4 | 四段IPv4顺序 |
| DHCP | 44/1 | 00关、01开 |
| 端口1波特率 | 151/4 | 小端无符号整数 |
| 端口1数据位 | 155/1 | 05～08 |
| 端口1停止位 | 156/1 | 01=1位、02=2位 |
| 端口1校验 | 157/1 | 00奇、01偶、02 Mark、03 Space、04无 |

115200、8N1在151～157为 `00 C2 01 00 08 01 04`；9600波特率为 `80 25 00 00`。旧网页结构注释出现0/1/2停止位，但其报文及WCH示例 `GetCurSel()+1` 和资源文件仅支持1/2，本实现采用后者。

## 读改写与验证

1. 必须先扫描获得MAC，打开弹窗GET完整快照。读取失败不得用默认值写设备。
2. 用户写入前再次GET，只在最新快照上替换编辑过的字段；这些字段若已被外部修改，终止并要求重新读取。其余字节（包括末尾51字节）原样保留。
3. DHCP开启时保留最新快照的IP/掩码/网关，不清零、不应用禁用控件中的草稿；编辑网络字段或切回静态模式时才校验并写入地址；仅改串口或名称时原样保留已有网络配置。静态网关允许0.0.0.0，否则需处于同子网。
4. GET等待1秒，最多3次。SET仅发送一次，不自动重复写入或发送额外复位命令。
5. SET发出后在15秒窗口内等待应答、按同MAC搜索并GET；ACK丢失也继续核对。DHCP开启不要求地址等于旧静态地址，其余目标字段必须一致。不假定固定重启时序，不自动重连TCP。
6. 状态区分已验证、读回不一致、写入结果未确认、设备拒绝。超时不等于设备未写入；再次写入必须重新读取。

软件允许输入300～10,000,000波特率，实际支持值取决于芯片版本与时钟模式；旧模块通常上限921600。读回一致仅证明参数存储一致，不代表串口链路在该速率下已经验证。
