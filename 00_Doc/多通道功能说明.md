# 多通道功能说明（V0.2.1，2026-10-03）

多通道功能现已整合到正式工程，沿用正式版应用名称、指令库、连接设置、收藏和历史。当前修复版本为V0.2.1，绿色包不含源码。保留正式CH9121读取修复与双向链路图标。

## 使用方法

1. 打开 `serial_test_tool.exe`，标题为“串口测试工具”，底栏左侧显示V0.2.1、正中显示链路状态、右侧显示AlanStewart。
2. 从“指令库”或“自动测试”点击“多通道计划”。先选择新协议CA、旧协议ASCII或旧扩展协议$/@，再填写实际设备名称、通道数、功能、通道范围和统一参数值。
3. 通道范围支持 `1-40`、`1,3,5-12`；“全部通道”按设备通道数填写范围。结果按升序去重。每次生成一种功能和统一值；可重复生成，组成多功能、多参数计划。
4. 默认勾选“设置后读回核对”。40个通道生成80步，每路先设置再读回；预览按协议显示实际发送报文及完整期望回复：新协议HEX自动追加BCC，旧协议ASCII不追加BCC。
5. 加入后默认遍历1轮。可调整遍历轮数；摘要显示换算后的总发送条数。设置/读回成对移动和删除。
6. 按实际设备选择连接参数并连接，启动测试。在“实时统计”或“结果与日志”查看逐步骤、逐通道结果及覆盖情况。
7. “保存计划/打开计划”保存报文、设备信息和测试设置快照；不需要把各通道录入指令库。重启也会恢复上次清单。

## 本次范围与判定

- V0.2.1统一以成功轮首字节统计响应时间；最大值保留整次测试历史最大样本，重新开始才清零。超窗口数据不参与本轮匹配。
- 点击停止立即停发，仅等待当前步骤的原有截止时间；仍须完整窗口精确比较，不会继续发送下一条设置或读回。断链/退出保留中断未完成，不提前计超时。
- 已发送为实际发送量；检测比率的分母为已结算的成功/错误/超时轮次。在途、中断数量单独显示；停止的计划不判全部合格。

- 新协议CA：亮度、脉宽、开关、光源延时、相机延时，通道编码1～255，实际能力按型号填写。
- 旧协议ASCII：亮度、脉宽、光源延时、相机延时；输入数字通道1～26，生成A～Z编码。普通旧协议的SW分区开关在参考源码中未实际保存，不作为通道开关模板。
- 旧扩展协议$/@：亮度、脉宽、开关、光源延时、相机延时，通道1～26映射A～Z。每路单独设置/读回，以便归属统计；暂不合并多通道块。写入回复$不含通道和功能，只能确认响应，推荐保留读回核验。
- 用户已确认A～Z编码能力；参考源码配置为8路，实际26路固件仍待验收。普通旧协议T/W亮度与ST内触发周期、SW分区开关重名，当前拒绝生成包含20/23通道的普通亮度计划，不会跳过通道或自动换协议；可用旧扩展协议，或显式选择1-19,21-22,24-26。专用规则确认后再开放冲突命令。
- 切换协议不自动缩减所选通道范围，例如新协议1-40切到旧协议仍保留范围并报错，避免悄悄漏测。
- 亮度255/999档位必须与设备当前模式一致；脉宽及延时默认显示原始值，单位标注不执行单位换算或设备模式切换。
- 生成计划使用完整响应窗口校验：从发送起累计到本步超时点，再逐字节比较。多余字节、错误通道、错误状态、错误读回值均不通过；分片到达不改变判断。成功响应耗时仍记录到首字节。
- 每步耗时约为“超时＋间隔”。默认间隔100ms、自动超时200ms，80步一轮约24秒，另加系统调度开销。
- 旧原始指令保持原有包含匹配行为。未实现CB及旧扩展多通道块打包；当前均逐通道测试。
- 逐通道核验必须同时满足设置和读回步骤的合格线；只设置时标为通信确认。未覆盖通道或计划未跑完显示未完成，不能据部分已通过步骤判整机合格。纯发送压测不作回复合格判定。
- 参数读回只证明协议参数一致，不等于真实亮度、脉宽波形或跨通道隔离已测量。协议无序号，超时后迟到的相同回复仍有配对局限。
- 单计划最多4096步、4MiB，单次最多1000万条请求。完整计划只展开一轮，重复执行不复制千万条数据。
- 每次启动在日志目录保存 `plan_*.json`；结果CSV包含通道结果与步骤快照。全量收发日志需勾选保存全量日志。

## 升级与试用计划导入

- 正式QSettings身份保持 `SerialTestTool/SerialTestTool`，用户指令库位置保持原样。
- 第一次启动先从原 `auto/playlistIds` 按顺序（含重复项）建立报文快照；原ID清单备份到 `auto/legacyPlaylistIdsBackup`。暂缺/禁用的旧项会提示并保留在备份中。
- 正式快照使用 `auto/playlistSnapshot`；损坏或超大快照保留原内容，并备份至 `auto/recoverySnapshot`。
- 试用设置不会整库覆盖正式设置。在试用程序点“保存计划”导出JSON，再在正式程序“打开计划”导入。继续支持schema_version=1及ca_v1/old_ascii_v1/old_ext_v1快照。
- 正式轮询列表现在保存加入时的报文快照；修改指令库不会自动改动已有计划，需要重新加入该指令。
