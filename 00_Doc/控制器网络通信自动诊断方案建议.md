# 控制器网络通信自动诊断方案建议

日期：2026-09-20。状态：讨论稿，未实施、未登记为已批准的新决策。

2026-09-21后续决定：用户已要求设定持续目标并分段执行，且明确独立软件、独立文件夹和名称。现按D-13在 `01_Software/controller_network_diagnostics` 实施，名称“控制器网络诊断工具”；完整范围/阶段状态见《控制器网络诊断工具实施计划》。本文保留最初讨论依据，其中“新增原工具页面”以独立应用方案替代。N0/N1已验证，后续功能仍按阶段推进；原始指令匹配边界仍适用，正式V0.2的D-12生成步骤另有strict_frame响应窗口，不应混同。

## 1. 目标与适用范围

用户希望在扫描控制器后，监视目标收发，选择指令自动检查通信；遇到无回复时检查电脑网络，再扩大指令轮询范围，帮助定位故障。

建议产品名称为“网络诊断”。输出应是“异常位于哪一层、已有证据、可能原因、下一步验证”，并明确已确认事实、疑似原因和未检查项。一次有限检查不能证明整台电脑绝对正常，也不能仅凭无回复认定控制器损坏。

暂按本电脑主动连接控制器设计，支持直连与经交换机/路由器连接；旁路监控取决于用户现场拓扑。第一期以现有 CH9121 TCP 透传为范围。

## 2. 监控能力边界

- 应用收发记录：只能看到本工具交给 socket 的字节、收到的字节和连接错误；现有 NetworkTransport 可复用。write/flush 成功不是对端收到或 MCU 已执行的证明。
- 网卡抓包：在正确接口采集目标相关 TCP、UDP、ARP、ICMP，可以观察握手、重传、复位、窗口及数据 ACK。抓包应先于连接开始。
- 普通交换机端口通常看不到控制器与其他电脑之间的单播通信；需要端口镜像或 TAP。混杂模式本身不能解决交换机未转发流量的问题。
- 用扫描报文头 MAC 关联设备身份，用 IP/端口关联通信端点；DHCP 变化后重新扫描确认并记录地址变化。同网段可以辅助核对 ARP；跨路由时二层目的 MAC 是下一跳，不能拿它与控制器 MAC 直接比较。
- 不能只用目标 IP 过滤全部诊断证据：ARP、广播搜索、DHCP 地址变化及部分 ICMP 错误需要另外保留。发现/ARP 数据按目标 MAC/IP 和时间窗口筛选。
- 抓包缺失、接口选错、采集丢包、网卡卸载都可能影响观察。不能把本机出站校验和异常或抓包漏段直接判为物理网络故障。

## 3. 分层检查

| 层次 | 检查内容 | 可以支持的结论 |
|---|---|---|
| 本机与路径 | 网卡启用/链路状态、IP/掩码、目标路由、实际源 IP 和出口、多网卡/VPN影响 | 确认本机配置或路径选择异常；检查通过只表示所检查项未发现异常 |
| 设备发现 | 选定网卡扫描、同 MAC 是否仍在线、IP 是否改变、可选只读配置获取 | CH9121 配置通道可达；不能据此认定 TCP 或 MCU 正常 |
| TCP | 目标实际服务端口、连接结果、握手、RST、重传、数据序号对应的 ACK、窗口 | 是否能建立连接、对端 TCP 栈是否确认数据；不能据此证明串口输出或 MCU 处理成功 |
| 业务协议 | 选定指令、回复完整性/关联性、响应时间、错误码与超时 | 指定协议和指令在本轮是否得到有效回复 |

直接 IP 通信不依赖 DNS；同子网直连不要求默认网关可达。不以“能否上外网”作为本机是否正常的判据。Ping 是辅助证据，失败不能单独判离线。跨网段广播搜索可能不可用，扫描失败与目标单播 TCP 不通不是同一结论。

实际链路：电脑 → 网络路径 → CH9121 TCP → CH9121 串口 → 控制器 MCU → 反向回复。网络抓包无法直接观察内部串口；当 TCP 数据已获 ACK 而业务无回复时，串口参数、线路、协议及 MCU 状态仍需进一步区分。

## 4. 建议自动流程

1. 扫描选择目标，冻结 MAC、当前 IP、端口、网卡、设备档案及指令计划；采集本机配置快照并启动可选抓包。
2. 检查目标路径，复用本工具已有连接或建立一条诊断连接。普通自动测试、手动发送及诊断发送互斥，防止交叉回复。不要另开并行 TCP 探测占用设备连接名额。
3. 顺序执行用户选定的诊断指令，每次只保留一个在途请求。
4. 发生无回复、断开或回复异常时，记录异常前后证据，再做本机路径、同 MAC 发现和 TCP 复核；明确本机异常时先给出处理建议。
5. 本机检查未发现明确异常且 TCP 可用时，先尝试少量已知有效的只读基准命令，再遍历兼容的诊断指令集合。TCP 持续不能连接时，标记指令项“未执行”，继续发库中指令不会增加诊断价值。
6. 找到有效命令后复测该命令及原失败命令，分别报告协议差异与间歇恢复；一次成功只能证明该时刻该命令可用。
7. 在总时限、重试次数或人工停止条件到达时结束，生成证据报告。连接重试与指令重试分别计数，有退避且有限次数；每次尝试保留原始结果，不把重试后的成功覆盖原失败。

建议初始参数（待实机标定）：TCP 连接超时 2 秒；只读指令超时 500 毫秒、间隔 100 毫秒；无回复最多追加 2 次尝试；快速诊断总时限 60 秒。扩展遍历运行前显示预计耗时，超过预算的项标记“未执行”。诊断超时独立设置，不直接使用现有 interval×2 的压测超时公式。

协议没有事务序号时，迟到回复可能污染下一轮。需处理接收残留、设置有限等待间隔、校验回复对应的命令/通道；歧义仍存在时报告“关联未确认”。TCP 按流累积，不能把单个数据包或 readyRead 当作完整协议帧。

## 5. 指令库如何复用

不默认发送完整的 132 条库。现有库含恢复出厂、保存 Flash、修改波特率和输出状态等操作，也有占位/禁用条目及不同产品协议。

建议维护独立“诊断档案”，引用 command_id 并保存运行快照，包含：适用型号/协议、允许自动诊断、只读或有副作用、优先级、回复规则、超时和允许重试。无法确认作用的指令默认不进入自动集合；不能仅靠中文名称含“读取”自动判定安全。跨协议探测也要核对目标兼容性，避免另一种协议下产生意外语义。

用户仍能像现在一样勾选测试内容；“扩展诊断”遍历全部适用且经过审核的只读命令。写操作作为单独的明确测试计划，不自动混入故障回退流程。

现有匹配存在两个边界：空期望收到任意字节即成功；非空期望用 contains 判断。诊断应区分“收到数据”“有效协议回复”“数据符合预期”。可分两步实施：

- 首期：固定回复使用完整回复规则；动态回复没有可靠校验时只标“收到数据，正确性未验证”。
- 后续：独立诊断校验器支持帧长度/帧头/命令号/通道/校验和等配置，或协议插件。收到合法错误回复说明协议有响应，但业务执行失败。

通用规则或协议插件都属于待确认的匹配能力扩展，不能静默改变 D-01 或现有测试统计。现有“丢包率”是应用轮次超时率，应与新增的 TCP 重传次数/比例分别展示。

## 6. 结论示例

| 证据组合 | 建议结论 | 后续检查 |
|---|---|---|
| 网卡禁用或目标路由选择了不适用的出口 | 发现本机网络配置异常 | 启用目标网卡或核对路由 |
| 同 MAC 搜索在线，TCP 连接失败 | 配置通道可达，透传服务不可用 | 核对端口、服务模式、连接占用及过滤策略 |
| SYN 多次发出，未见返回 | 目标 TCP 无响应，原因未定位 | 核对路径、设备供电/服务及防火墙；先确认抓包完整性 |
| TCP 建立，承载指令的数据获 ACK，无业务回复 | TCP 数据已获确认，业务回复链路异常 | 核对 CH9121 波特率/校验、内部串口、命令格式及 MCU |
| 某协议查询连续有效，原指令仍失败 | 该协议部分通信可用，原指令兼容性/参数待查 | 核对型号、通道、协议版本及期望值 |
| 抓包看到回复晚于应用超时 | 发现迟到回复，可能是超时预算不足 | 对比设备处理时间、串口耗时及网络抖动 |
| 现有软件判失败，但完整回复符合已核实的协议 | 测试配置或匹配规则可能错误 | 复核期望值、BCC及成帧规则 |

防火墙开启本身不是故障证据；单独 RST 也不能证明其他软件占用。无法访问的系统信息列为“未检查”，不列为“通过”。

## 7. 界面、报告与实施顺序

新增“网络诊断”页：目标/网卡信息、可选检查项、只读诊断指令列表、开始/停止、分层状态及证据详情。支持“主动诊断”和“仅监视”；仅监视不会发送指令，也不能完成依赖主动请求的检查。

报告记录目标 MAC/IP/端口、实际源 IP/接口、配置快照、每次指令原始收发/校验结果/耗时、重试与重连、已检查及跳过项、结论和后续建议。抓包可用时附 pcapng，应用时间与抓包时间统一关联。

建议分两期：

1. 基础诊断：现有扫描/TCP/指令计划复用，本机检查、只读白名单、分层规则和报告。无抓包时明确缺少 ACK/重传证据，仍能完成基础诊断。
2. 抓包增强：通过 Npcap + dumpcap 采集、TShark 提取分析，加入重传/RST/窗口/ACK与异常前后证据。使用容量受限的环形文件、异步解析及 UI 限频；部署前核对依赖安装和分发条件。

如首版就需要证明“已发数据是否获得 TCP 确认”，抓包增强必须进入首版范围。无须自行实现完整 Wireshark 界面或 TCP 分析器。

软件自动执行已选择的检查和有限重试；自动改 IP、关闭防火墙、改串口参数、重启或恢复出厂不属于此诊断流程。

## 8. 验收用例

- 网卡禁用、网线断开、选错出口、没有适用路由：指出本机/路径证据。
- Ping 被阻止但 TCP/指令正常：不能判网络故障。
- 同 MAC 在线但端口错误、服务不可用：分别显示扫描与 TCP 结果，不能直接判 MCU 故障。
- TCP ACK 正常而内部串口参数错误：定位到业务回复链路，不能声称已经确定是波特率问题。
- 错误协议、动态回复、合法错误帧、TCP 分片/合并、迟到回复：不把任意字节当协议通过。
- DHCP 地址改变、跨网段、多网卡/VPN：记录目标身份与实际路径；跳过不适用的广播/ARP推断。
- 抓包缺失/权限不足/丢包/校验和卸载：标记证据限制，基础诊断继续。
- 基准命令成功而原命令失败、偶发恢复：保留各尝试，不掩盖原故障。
- 自动遍历不发送恢复出厂/保存Flash等条目；取消后不再发送，日志保留。
