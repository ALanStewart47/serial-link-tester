# Command Atlas 分阶段开发计划

> 产品中文名：控制器指令助手。按阶段交付，每阶段由用户完成界面与功能验收后再进入下一阶段。

## 产品与平台

- 英文名 **Command Atlas**，程序名 `CommandAtlas.exe`；Qt 6.11.2、MSVC 2022 64-bit / v143、Qt Widgets、C++17、CMake + Ninja。
- 工程独立放在 `01_Software/command_atlas/`，应用配置与数据身份独立于串口测试工具和网络诊断工具。
- 正式数据来源为本地 GitLab 上公开仓库的 `main` 分支；客户端匿名读取，不做账号管理。研发用 GitLab 本地录入/导出与 MR/主分支治理维护正式数据。
- 首版只做中文名称、用途、别名、关键词和同义词检索；参数填写、指令组帧、复制和静态导出，不连接控制器、不发送指令。
- 查询、模板数据和数据校验彼此分层。正式格式包含产品档案、指令模板、同义词与版本清单；帧以有序固定段、参数段和受限计算段组成。初期参数类型为整数、枚举、定长 ASCII、ASCII 数字；校验支持 XOR BCC，不支持的规则应报错，不执行数据中的脚本。

## 阶段交付

| 阶段 | 交付 | 用户验收重点 |
|---|---|---|
| S1 本地查询与组帧 | 独立可运行应用；12 条新协议、旧协议、旧扩展协议样例；产品/协议选择、中文检索、条目详情、参数表单、HEX/ASCII 预览与复制。 | 中文用途检索；修改通道/参数后的帧字节、文本和 BCC；越界输入被阻止。 |
| S2 研发录入工具 | 本地草稿编辑、复制、参数/段定义、预览、保存/重开、导出及导入标准 JSON；草稿不改正式库。2026-10-03导入缺口已修补并完成代表场景复验，阶段仍待用户确认及剩余验收。 | 不写 JSON 也能录入；定义参数位置、编码、范围、默认值；导出后重新导入一致（同ID另建时仅ID变化）。 |
| S3 GitLab 同步与离线 | 仓库地址/项目配置、后台检查 main、固定提交下载、校验后原子启用本地快照；失败保留旧库；模板仓库和 main 维护说明。 | 更新同步、断网/错误数据回退、离线重启。 |
| S4 设计落地与首版整理 | 接入美术设计规范和图标；收藏、最近使用、静态导出、使用说明与发布目录。 | 售后查询流程、界面易用性、目标电脑运行。 |

美术已于 2026-09-28 定稿为“工程图集 · 字段解剖”：采用双栏查询、分组字节图，融合 Atlas 蓝与浅色控件规范。正式约束见 `00_Doc/Command_Atlas_美术定稿_V2.md`，预览见 `01_Software/command_atlas/design/approved.html`。S2/S3新增页面按此组织，S4统一接入主题、字段图和正式图标；候选中的扩展功能不自动纳入范围。

## 工具链与检查分工

- 当前安装有 Qt 6.11.2 `msvc2022_64` Kit 与 CMake/Ninja；已向现有 Visual Studio 18 Community 安装补齐 MSVC v143 x64/x86 工具集，确认目录版本 `14.44.35207`。MSVC 14.50 保留但不用于本工程。
- 助手只做必要基础检查：CMake 配置/构建链接、编译告警、代码差异和资源引用、JSON 格式/必填字段/引用关系；不建立复杂自动化测试体系，不做自动 GUI、设备模拟或压力测试。
- 2026-10-03用户明确授权助手启动程序并开展S2原生GUI验收，作为上述默认分工的本次例外；使用现有运行程序逐项操作，不建立复杂测试体系、不连接设备。通过项、未通过及未覆盖项分别记录于工程README。
- 每阶段提供运行目录、变更摘要与约 5 项人工操作步骤。用户负责实际 UI、检索效果、指令字节、同步、离线和现场验收；验收通过前不推进后续阶段。
- 首阶段配置默认内嵌只读资源，正式同步与研发编辑留在 S2/S3；不读取旧工具的用户设置或覆盖其数据。
