# 关键问题总结（上位机联调）

来源：`cst_isp_flasher` 开发与真机日志，以及对照固件。协议字节级说明见 [PROTOCOLS.md](PROTOCOLS.md)。

读这份的目的：下次再看到「超时 / CRC 失败 / 读不到版本」，先对号入座，不要重新从固件翻起。

---

## 1. 看起来像上位机，其实是 Boot 的问题

### 1.1 DMA 剩余计数截成 8 位（新 STM32 Boot，已修）

**现象（日志已钉死）**

1. App 触发成功：`TX FA 68 AA 00 00 54 C0` → `RX 73`。
2. 等复位后发块大小：`TX FA 68 AA 01 00 C4 C1`。
3. Boot **有回包**，但是 `RX FA FF FF FF FF 80 FD`（CRC 失败应答）。
4. 上位机状态机当时没处理 `CrcErrorAck`，界面报「块大小命令超时」。
5. 再点一次升级：触发也变成 `FA FF…`。不是 App 死了，是板子还停在 FPGA Boot（`0x08003400 = 0x55`），App 已经不在。

**根因**

新 Boot 为吃 FPGA 大包把 `BUFFER_SIZE` 设成 **2148**，但 `uart_receive()` 用 `unsigned char numb` 接 `__HAL_DMA_GET_COUNTER()`。

7 字节命令：剩余 2141 → 截成 93 → `rx_length = 2148 - 93 = 2055` → 按 2055 字节算 CRC → 必失败。

**修复**

`00_Reference/legacy/BootLoader/MDK-ARM/APP/Src/uart.c` 里 4 处 `numb` 改为 `uint16_t`。必须重新编译并烧录 **Boot**，不是重编上位机。

卡在 FPGA Boot 时：断电，或把 `0x08003400` 半字清掉，否则触发帧永远进不了 App。

**芯片页大小**：TPS481500C 是 **STM32F103CBT6，1KB 页**。`FLASH_PAGES = 1024` 是对的。Keil 设备选成 F103xG 只是旧工程方便，**不要改成 2048**。

### 1.2 IDLE 里 `delay_ms(3)`（新 Boot，能干活但别扭）

新 Boot 的 IDLE 先走 `HAL_UART_IRQHandler`，再在中断里 `delay_ms(3)` 才读长度。GD32 参考是 IDLE 里当场停 DMA、算长度。日志证明 RX 能通，不是 1.1 的主因。不要把「再加延时」当升级失败的第一手段。

### 1.3 安路 App 用栈上 1 字节 DMA 发 `73`

`fpga_upguade_cmdhandle()` 里 `uint8_t tx_buffer[1]={0x73}` 直接 `HAL_UART_Transmit_DMA`。函数返回后缓冲区失效，USART3 上可能发不出 `73`。USART1（网口）有时仍能看到应答。触发「串口没 73、网口有 73」时先查这个，不是波特率。

## 2. 协议语义，写错一次就会全线失败

| # | 事实 | 写错会怎样 |
|---|---|---|
| 1 | FPGA CRC16 是 Modbus（`0xA001` / `0xFFFF`），**大端先发**（`crc >> 8` 再低字节） | 全程 `FA FF FF FF FF …` |
| 2 | `FA 00 xx xx xx CRC` 的参数是 **总块数**，不是字节数 | 擦完过早结束或永远等不到写完 |
| 3 | 写块地址是 **1-based 块索引**，不是 Flash 字节地址 | 写到错误偏移或判完成条件错乱 |
| 4 | `73` 在中断里立刻回，**不代表擦/写完成** | 下一帧被丢，回 `FB 01 FB` |
| 5 | 忙时（`up_cmd != 0`）任何帧当状态查询，数据帧被丢 | 必须轮询到 `FB 00 FB` 再发下一块；忙则重发**同一块** |
| 6 | 写块帧长度必须是 `7 + blockSize`。末块不足要 `0xFF` 补齐 | 短帧被静默丢弃，不回 `73` 也不回 `FA FF` |
| 7 | MCU 数据包 XOR8 只异或 **256 字节 payload**，不含头 | 每包 `72 68 03 16` |
| 8 | MCU 触发目标版本必须 **≠ 当前版本** | 只回版本号，不进 Boot |
| 9 | 分帧靠 UART **IDLE**，没有长度字段 | 一帧拆开发、中间有空闲，对端当成两帧 |

安路 App 触发判定：`FA 68 AA` 且 `buf[3]<=8 && buf[4]==0x00`。块大小 `256 = 0x0100` 也满足这个条件。所以 **还在 App 时不要发「设块大小」**，会再次触发复位。工具必须先确认已经进 Boot（`73` 后等复位，或收到 `65` / beacon）。

`FA 68 AA 00 00` 在 App = 触发；在 Boot = 块大小 0 → 回 `65`。工具用 `65` 判断「已经在 FPGA 升级模式」。

## 3. 通道和波特率

### 3.1 网口改不了波特率

CH9121 是 UART 透传。`IspNetworkTransport::setBaudRate()` 是空操作。网口上 App / Boot **只能都是 19200**（走 USART1）。

安路 FPGA **直连 USART3** 才是「触发 19200 → 烧录 115200」。把直连的 115200 套到网口，写块阶段会全无应答。

### 3.2 本系列 MCU 不要默认 115200

README 里 G4 Boot「复位后 115200」是**另一款产品**。TPS481500C / 新 STM32 Boot：App 与 Boot 都是 **19200**。MCU 页默认「与连接相同」，不要把默认 Boot 改回 115200。

### 3.3 失败后标志不清除

| `0x08003400` | 上电走 |
|---|---|
| `0x00AA` | MCU 升级 |
| `0x0055` | FPGA 升级 |
| 其它 | 跳 App `0x08003800` |

升级失败停在 Boot 时，标志还在。再发 App 触发会得到 Boot 的 CRC 错包或无 `73`。先断电或清标志。

### 3.4 高云网口看 App 版本

- `V1.6_origin`：USART0 = CH9121 @ 19200，进主机协议，网口触发可用。
- 现用 `CST-BPS24200CIP6-6TDP-MCU-V1.6`：USART0 改成串口屏 115200，**不进主机协议**，网口自动触发不会成功。新面板用串口。

### 3.5 CH9121 扫描器必须单例

UDP 50000 不能在进程里绑两次。MCU / 安路 / 高云三页共用一个 `Ch9121Scanner`。TCP 数据口默认 **6600**。

MCU 触发后复位，有的 CH9121 会掉 TCP。FPGA 用约 3s settle + 重发探测；MCU 用总包数探测。若整颗 CH9121 被复位，可能要重连后再探测。

### 3.6 网口升 MCU 先查 F0

只对 **MCU 网口**发 `72 68 F0 16`（App 一次、进 Boot 再一次）。超时或 `ver == 00`、第二次不是 Boot 在答，弹窗「不支持网口升级」，**不自动切串口**。FPGA 网口和串口升 MCU 不发。新 App 配旧 Boot 时第一次会放行，第二次拦住。

### 3.7 自定义波特率不要写进 QSettings

工厂电脑上一次改成 115200，下一班会「读不到版本」。会话内改、重启回 19200。

## 4. 机型不要混用

| 机型 | MCU | FPGA 落盘 | 直连烧录波特率 | beacon `FA 68 01 16` |
|---|---|---|---|---|
| TPS481500C 安路 | STM32F103CBT6 | 外部 W25Q128 @ `0x0C0000`（12×64KB） | USART3 **115200**（旧 Boot） | 进 FPGA Boot 时发一次 |
| 高云 / BPS | GD32 | FPGA 内部 Flash（JTAG） | 默认 **19200** | **不发** |
| 新 STM32 Boot | 同一颗 F103CBT6 | 按编译配置（移植自 GD32） | USART1 **19200** | 视移植而定 |

上位机用 `FpgaUpgradeProfile::anluProfile()` / `gowinProfile()` 区分超时和文案，线格式仍是同一套 FA/FB。

高云末块后 MCU 会复位，TCP/串口掉线是预期。`WaitingLastBlockSettle`（约 2.5s）期间掉线视为成功。

## 5. 工具链和实现坑

- **只用 Qt 6.5.3 mingw_64**。6.10 官方包没有 SerialPort。
- Qt 6.5 的 UDP：`writeDatagram(data, host, port)`；`readDatagram` 后按实际长度 `truncate`。6.7+ 的短参数 API 在 6.5 不存在。
- `quint16(char)` 会符号扩展，先转 `quint8`。
- MinGW 的 `windeployqt` **不要**加 `--release`，否则跳过无 `d` 后缀的 `qwindows`，双击闪退。
- 发布必须带 Qt DLL + `platforms/` + MinGW 运行库，不能只拷 exe。
- IDLE 路径：`HAL_UART_IRQHandler` 之后再算长度；测试里 mock 发送次数容易多数一帧。

## 6. 上位机状态机已知缺口

`FpgaProtocol` 能解析 `CrcErrorAck`（`FA FF FF FF FF 80 FD`），但 `FpgaUpgradeController` **没有按它失败或改提示**，用户只看到超时。再碰到「日志有 RX、界面说超时」，先把 hex 对一下是不是这帧。

MCU 状态机不依赖 Boot 主动发 `72 68 01 16`：settle 后主动发总包数，收到 `02` 就开写。

## 7. 已经做成的产品决策（不要无故改回去）

- 文案是「串口 / 网口」，不是「串口直连 / CH9121 网络」。
- **v1.1**：连接栏在三个页签上方共用；页签只做协议操作。提示「先连上控制器再选升级页」。
- MCU Boot 波特率：MCU 页下拉 + **与连接相同**（默认勾选）。
- 不要主题切换。主色是亮薄荷绿 `#0ca678`。
- 不要把 FPGA 的双波特率藏进二级菜单（安路直连必须能改触发/烧录）。
- 本工具与 `upper_upgrade`（CRC32/槽位）完全无关，不要混协议。
- 页脚左下角版本号（双击彩蛋图）、右下角 Author（连点 8 次致谢）不要改回旧布局。

## 8. 对照日志速查

| 日志 | 含义 | 下一步 |
|---|---|---|
| `TX FA 68 AA 00 00` → `73` | App 接受 FPGA 触发，将写 `0x55` 并复位 | 等 settle，再按 **Boot 波特率** 探测 |
| `73` 之后块大小得到 `FA FF…80 FD` | Boot 在，但当 CRC 错 | 查 RX 长度 / `numb` 是否 uint16；不要怪帧内容 |
| 第二次触发也是 `FA FF…` | 仍停在 FPGA Boot | 断电或清 `0x08003400` |
| 触发回版本号、不进 Boot | MCU 目标版本 == 当前版本 | 改目标主.次 |
| `65`（块大小） | 非法块大小，或 App 已不在、Boot 把 `00 00` 当块大小 0 | 已在 Boot 则正常，直接设合法块大小 |
| `FB 01 FB` | 忙（擦或写） | 重发同一块，不要加序号 |
| 网口触发无 `73`（高云新面板） | USART0 不是 CH9121 | 改用串口，或换 `V1.6_origin` |
| 直连安路写块全超时、触发却成功 | 烧录还停在 19200 | 直连切 115200；网口不要切 |
