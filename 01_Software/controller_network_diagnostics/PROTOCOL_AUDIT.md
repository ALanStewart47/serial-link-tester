# 诊断查询审核与完整回复校验

2026-09-21，规则版本 `reference_protocol_v1`。仅在独立诊断软件生效，不改变原串口工具的匹配或统计。依据仓库 `00_Doc/protocol_doc_code/protocol_new_handle.c`、`protocol_old_handle.c`、`protocol_old_extend_handle.c`、`protocol_public.c` 和 `00_Doc/serial_protocol_summary.md`。这些是参考实现，不能自动推断所有型号均支持。

## 门禁

必须有本次明确确认的型号/固件、协议、通道数和支持功能。实际报文决定所属功能；导入ID、名称、功能组和批准字段不是安全依据。格式错误/禁用/写入/未知命令仅保留展示，不进入选择或回退集合。相同发送报文在回退集合去重，心跳或通道数/型号查询优先。

| 请求类型 | 允许范围与额外条件 | 回复规则 |
|---|---|---|
| CA | 完整6字节、正确BCC；61～65、81～88、A1～AA；查询数据为0；通道型1～档案通道数，全局通道0 | 完整6字节，头/命令/通道相同，BCC正确；4字节同字段且末字节01/02/03为合法错误 |
| CC参数 | 完整7字节、正确BCC；32～3E；配方/触发源均1，数据为0 | 完整7字节，头/命令/配方/源相同，BCC正确 |
| CC表格 | 完整9字节、正确BCC；31；配方/触发源1，行1～64，通道数1～档案上限 | 完整13+2×通道数字节，前8字节对应请求，BCC正确 |
| CC错误 | 对应当前CC命令 | `CC cmd 00 01`不支持；`CC cmd field 03`字段超范围，参数field=1/2、表格field=1～4；不当成数据成功 |
| 旧ASCII | CST或CST#；SA#类、SPA#、SPUA#、DLA#/DCA#及ST#/SW#/T#/TR#/CT#/DC#；通道A～Z且不超档案 | 固定回复、固定前缀+数字或枚举，要求完整长度；ST是周期、SW是分区，不误作T/W亮度 |
| 旧扩展 | @01/02/03/04/05/06/07/08/09/11/13，完整通道列表和#，通道合法且不重复；04/08/09仅单字母 | @功能号、按请求顺序逐通道+4位数字、#；完整长度一致 |

原出厂库CC31使用7字节占位，缺行/通道数，不能自动执行；如导入符合上表的9字节帧可审核。CB、CC写入/复位/擦除、恢复出厂/保存Flash、修改波特率、输出控制和拼接查询+写入始终被排除。旧扩展00/10/12在参考固件中未实现，排除。

## 回复含义

校验必须在引擎完成本轮响应窗口后进行，不能每次readyRead提前通过；测试覆盖截断、追加噪声、两帧合并、错命令/通道及BCC异常。没有期望值时可确认结构有效，`expectation_checked=false`；有期望值再做完整字节比较。合法错误帧证明协议有响应，不能当作业务成功。

本规则不提供事务唯一性证明。执行器复用一条持久TCP会话，每条发送前等待安静窗口并收满响应窗口；步骤间迟到数据单独记为outside_response_window证据，不参与下一条匹配。回退集合排除已选择的相同请求字节，减少原请求迟到回复被立即误关联的机会。相同查询的迟到回复、回显和没有事务号的协议仍无法被完全消歧，某些查询请求与全零数据回复也完全相同，因此不能凭校验结果单独证明MCU执行。

## 独立导入与限制

原132条库作为独立资源副本（SHA256 `C1F425586D09279FA6A14CF917D8C62133819E18040F6F2E6657456C6C8A5D18`）。JSON数组最多4096条/4MiB，报文最多1024字节。ASCII拒绝有损字符转换及未知转义，HEX拒绝半字节/非法字符。导入副本写入独立应用数据路径；结构错误不部分替换。仅当前源JSON+已解码字节形成计划快照，不能从外部JSON继承自动发送批准。

本次验证为软件级，不含真实控制器指令发送。N3执行器、异常后本机复查/只读扩展查询/成功基准与原失败复测已实现并通过模拟回归；真实旧协议控制器仍待新版实机验收。N4抓包与N5完整验收仍待实施。
